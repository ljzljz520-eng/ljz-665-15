# 设备管理模块（状态流转）

## 功能概述

设备台账管理，核心是**设备状态流转限制与操作留痕**：

- 新建设备默认状态为**在用**；
- 状态范围：`在用(1)`、`维修中(2)`、`停用(3)`、`报废(4)`；
- 状态只能按下面的流转矩阵变更，不能通过“编辑”接口直接改状态；
- **报废是终态**，报废后不能再回到在用（也不能变更为任何状态）；
- **维修中 → 在用（维修恢复）必须填写说明**；
- 每次状态变化写入 `biz_device_status_record` 操作记录表，可随时按设备追溯。

## 状态流转矩阵

| 当前状态 \ 目标状态 | 在用 | 维修中 | 停用 | 报废 |
| --- | :---: | :---: | :---: | :---: |
| 在用 | — | ✅ | ✅ | ✅ |
| 维修中 | ✅（**必填说明**） | — | ✅ | ✅ |
| 停用 | ✅ | ✅ | — | ✅ |
| 报废 | ❌ 终态 | ❌ | ❌ | — |

> 同状态提交（如在用→在用）会被拒绝；非法目标状态码会被拒绝。
> 校验在后端 `DeviceStatusEnum` + `DeviceServiceImpl#changeStatus` 统一执行，前端按钮仅做体验层限制，绕过前端同样无法违规流转。

## 后端实现

模块：`backend/jeecg-boot-module/jeecg-module-device`（包名 `org.jeecg.modules.device`）

| 类型 | 类 | 说明 |
| --- | --- | --- |
| 枚举 | `enums/DeviceStatusEnum` | 状态码、中文名、流转白名单 `allowedTargets()`、维修恢复判定 |
| 实体 | `entity/Device` | 设备台账（表 `biz_device`），`status` 为状态码 |
| 实体 | `entity/DeviceStatusRecord` | 状态流转记录（表 `biz_device_status_record`） |
| 入参 | `vo/DeviceStatusChangeVO` | 状态变更入参：id、目标 status、remark |
| Service | `IDeviceService` / `DeviceServiceImpl` | 新增（默认在用+初始记录）、编辑（不改状态）、状态流转（校验+留痕） |
| Service | `IDeviceStatusRecordService` / Impl | 写操作记录、按设备分页查询记录 |
| Controller | `controller/DeviceController` | 设备 CRUD、`/changeStatus`、`/statusRecord/list` |

接口前缀：`/device/device`

| 接口 | 方法 | 说明 |
| --- | --- | --- |
| `/list` | GET | 设备分页查询（支持编号/名称/状态筛选） |
| `/add` | POST | 新建设备（后端强制在用，并写“新建设备，默认在用”记录） |
| `/edit` | PUT/POST | 编辑基础信息（状态字段以数据库为准，不会被修改） |
| `/changeStatus` | PUT/POST | 状态变更，body：`{id, status, remark}` |
| `/queryById` | GET | 设备详情 |
| `/delete`、`/deleteBatch` | DELETE | 删除 / 批量删除 |
| `/statusRecord/list` | GET | 某设备的状态流转记录（`deviceId` 必填，按时间倒序） |

流转与留痕在同一事务（`@Transactional(rollbackFor = Exception.class)`）：更新设备状态与写入操作记录要么同时成功，要么一起回滚。状态变更同时带 `@AutoLog`，也会进入系统操作日志。

## 前端实现

目录：`frontend/src/views/device/device/`

- `DeviceList.vue`：设备台账列表（状态彩色标签、按状态筛选、行内“状态变更/流转记录/编辑/删除”；报废设备不显示“状态变更”入口）；
- `components/DeviceModal.vue`：新增/编辑弹窗（不提供状态编辑）；
- `components/StatusChangeModal.vue`：状态变更弹窗，只列出当前状态允许的目标状态；维修→在用时说明框标红必填；选“报废”给出终态警示；
- `components/StatusRecordDrawer.vue`：右侧抽屉展示该设备全部流转记录（变更前→变更后、说明、操作人、操作时间）；
- `device.api.ts`：接口封装，`DEVICE_STATUS_TRANSITIONS` 与后端流转矩阵保持一致；
- `device.data.ts`：表格列、搜索表单、表单结构定义。

## 数据库初始化

### MySQL

- 脚本：`backend/db/device_module.sql`（建表 + 菜单/按钮权限 + 管理员角色授权，幂等，可重复执行）；
- 若开启了平台 Flyway（仅 MySQL 支持），已提供迁移脚本：
  `backend/jeecg-module-system/jeecg-system-start/src/main/resources/flyway/sql/mysql/V3.9.1_2__device_module.sql`，
  启用 `spring.flyway.enabled=true` 后启动会自动建表并写入菜单。

### SQL Server

- 脚本：`backend/db/device_module_sqlserver.sql`（由 MySQL 脚本经项目自带转换器 `db/sqlserver/convert_mysql_to_sqlserver.py` 生成，并补回设备编号唯一索引、将 `NOW()` 替换为 `GETDATE()`）；
- Docker Compose 一键启动时，`db-init` 容器会在主库脚本执行完成后**自动执行**该脚本（见 `db/sqlserver/Dockerfile`、`entrypoint.sh`），无需手工操作；
- 已有环境手工执行时，注意脚本为“直接建表 + 插入菜单”，重复执行前请先清理或自行加存在性判断。

### 菜单

脚本会写入一级菜单“设备管理”和子菜单“设备台账”，前端组件路径 `device/device/DeviceList`，并附带按钮权限：

`device:device:add` / `edit` / `delete` / `changeStatus` / `statusRecord`。

> 脚本默认把权限授予“管理员”角色（ID `f6817f48af4fb3af11b9e8bf182f618b`）。其他角色需要在“系统管理 → 角色权限”中勾选授权。
