# 设备状态流转

设备管理模块提供设备台账与**设备状态流转控制**能力。状态规则在后端强制校验，前端仅做交互约束，无法通过绕过页面的方式违反规则。

## 1. 状态定义

| 编码 | 状态 | 说明 |
| --- | --- | --- |
| `1` | 在用 | 新建设备的默认状态 |
| `2` | 维修 | 设备送修/维修中 |
| `3` | 停用 | 暂停使用 |
| `4` | 报废 | **终态**，不可再变更 |

枚举定义见后端 `org.jeecg.modules.device.enums.DeviceStatusEnum`，前端镜像常量见 `src/api/device/device.data.ts`。

## 2. 流转规则

| 当前状态 | 可流转到 | 备注 |
| --- | --- | --- |
| 在用 | 维修 / 停用 / 报废 | 新建设备默认为在用 |
| 维修 | 在用 / 停用 / 报废 | **恢复为在用时必须填写说明** |
| 停用 | 在用 / 维修 / 报废 | 停用后可重新启用 |
| 报废 | （无） | 报废是终态，**不能再回到在用**，也不能改为其他状态 |

另外：

- 不允许变更为相同状态（重复提交会被拒绝）；
- 设备状态**不能通过普通编辑接口修改**，只能走专用的状态变更接口 `PUT /device/device/changeStatus`；
- 所有规则在后端事务内校验，非法流转返回错误提示且数据不变。

## 3. 操作记录（可追溯）

每次设备状态变化都会向 `device_status_record`（设备状态流转记录表）写入一条记录，内容包括：

- 设备ID、设备编号、设备名称；
- 变更前状态、变更后状态；
- 变更说明（维修恢复时必填）；
- 操作人、操作时间。

记录支持两种查看方式：

1. 设备列表行内「操作记录」：按设备查看时间线；
2. 顶部菜单「设备管理 → 操作记录」：跨设备分页查询全部流转历史。

新建设备时也会写入一条“新建设备，默认状态：在用”的初始记录。

## 4. 接口一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/device/device/list` | 设备分页列表 |
| POST | `/device/device/add` | 新建设备（强制默认“在用”，写初始记录） |
| PUT | `/device/device/edit` | 编辑设备基础信息（不允许改状态） |
| PUT | `/device/device/changeStatus` | 状态流转（校验规则 + 写操作记录） |
| GET | `/device/device/allowedTargetStatus?status=` | 查询某状态允许的目标状态 |
| GET | `/device/device/statusRecord?id=` | 单设备流转记录 |
| GET | `/device/statusRecord/list` | 全部流转记录分页 |
| DELETE | `/device/device/delete`、`/deleteBatch` | 删除/批量删除 |

状态变更请求体：

```json
{
  "id": "设备ID",
  "targetStatus": "1",
  "remark": "维修恢复说明（维修→在用时必填）"
}
```

## 5. 数据库与菜单

- 表：`device`、`device_status_record`；
- 菜单：设备管理（设备列表、操作记录）与按钮权限（新增/编辑/删除/状态变更）。

全新环境执行 `docker compose up -d` 时会随初始化脚本自动创建；已初始化过的环境可执行幂等升级脚本：

```
backend/db/upgrade/V20261002__device_module_sqlserver.sql
```

执行后重新登录（或重启后端刷新菜单缓存）即可看到「设备管理」菜单。
